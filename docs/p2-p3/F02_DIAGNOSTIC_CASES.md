# F02 diagnostic cases: pose, SALSA, animation, grip, and prepared partner

This catalog records the diagnostic purpose that must survive retirement of the eleven historical scenes. It identifies executable assertions and reusable runtime types; the scene is not the test's owner. This pass is limited to the pose/SALSA/animation/grip/partner cases requested for this ticket.

The classification is deliberate: deterministic checks belong in EditMode tests or direct asset validation; inspection belongs in an asset preview command/window; actual audio-driven or body-composition observations remain manual. The current Unity Play boundary still applies. No case below claims visual approval.

## Migration and retirement gate

- Before deleting any scene, search literal, concatenated and serialized callers for its path. The mapped old callers include `DazPoseEditorCommands`, `RemediationContentPreflightRunner`, `PerformerSalsaConfigurator`, `AnimationAuditValidation`, `LaraHumanoidKawaiiTestSetup`, `HandGripAcceptanceSetup`, `PartnerCharacterPreparation`, and their legacy builder/runner wrappers. Replace each with an explicit asset/performer/context input; a path rewrite into another lab scene is not migration.
- Move assertions out of the large `PerformerPoseAcceptanceHarness` only by owned behavior. Its pose-transition, expression, speech, gesture/action, gaze/breathing, and dissolve checks are separate runtime suites; do not preserve the entire harness merely because one diagnostic case uses its actor. This document does not disposition those other suites.
- Retire scene-builder entry points only after their useful operations have a clear service/test owner. Temporary fixtures must restore/destroy objects and avoid saving user scenes, prefabs or source assets. Keep exact protected source and review evidence intact.
- No generic `DevelopmentLab` is justified by these five cases: deterministic checks are scene-free, and visual inspection can use an asset preview or the maintained Showcase/new Studio. If implementation proves a specific inspector interaction impossible with those tools, document that exact missing operation and user-visible need before proposing one minimal lab.
- Acceptance is a test or command that executes and reports the listed assertions without referencing any of the eleven retired scene paths. Static scene inspection alone does not pass this gate. Human visual review, where needed, remains a separately recorded result.
