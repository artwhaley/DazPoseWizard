# C05 — Correct the global selectable-card catalog before expanding scenes

**Dependency:** C00–C04. This ticket is a user-required correction to content ownership, NOT a new Director design. Current code compiles 18 cards inside `FirstContact.dazstory` and `StoryDirector` selects from the current `CompiledStoryProgram`; do not leave card discovery tied to one scene's source file.

## Exact product contract

> Scenes do **not** declare what libraries or card sets they use. There is a **global pool of selectable cards**. Director queries match **tags and runtime eligibility**. Adding a new tagged card makes it eligible in old scenes without editing those scenes.

- `Director.DrawAndExecute(tags:[Warmup])`, `[Main,Sitting]`, equipment-selected queries retain current semantics.
- Explicit `play Intro` remains an authored, potentially untagged narrative card. `Director.Execute(CardName)` uses an explicit named ID, not a scene library selection.
- Tags classify; universal physical state/consent/gear requirements filter. Do not conflate them. Future `equipment:spreader` cards must work without modifying old scenes or adding booleans to the world model.
- Keep seeded selection RNG, recency, cooldown, maximum uses, progress/pacing, intensity and debug reasons unchanged with an unchanged candidate population.

## Deliverable design — deterministic global content discovery

1. One **global selectable-card index/provider** owned by application/content, not any scene. Index **all tagged, published production card declarations** by recursively discovering `.dazstory` files in `Assets/Production/Story/Cards/`. This is the publication root for Task 1; current embedded tagged cards migrate there. Files elsewhere remain local/examples/test content and are not implicitly published. No manually curated card list, no scene registration, no scene-specific catalog fields. Future files placed in the published global content root must be automatically recognized after import/reindex; a generated project-wide index for builds is allowed and must be automatic.
2. Preserve `.dazstory` as author-facing source. Extract the current 17 tagged engineering cards into one or more reusable global-card `.dazstory` source assets. `Intro` can stay as First Contact's explicit local card. Do not create duplicate definitions or change their body/choreography. Preserve authored behavior and asset references. Record old-to-new declaration provenance and report accurate new file/line/column locations after extraction; do not preserve stale line numbers. Use the existing compiler and one execution/interpreter semantic model.
3. Build an import/link stage that assembles scene sequence + local explicit cards + **global selectable cards** into runtime-executable content without script files naming libraries. Current `CompiledStoryProgram` contains flat `instructions`, `expressions`, `entries`, `cards`, `bindings`, `dialogue`; a linker must remap every index and jump target correctly: instruction offsets, expression indexes in arguments/conditions, loop/jump targets, entry boundaries, `CardRequirement.Expression`, binding-use instructions, source maps and dialogue entries. Or implement an equivalent cross-program dispatch while keeping a single StoryMachine/Director behavior. **Do not simply concatenate flat arrays without relocation.**
4. `StoryMachine`/`StoryDirector` query the assembled global selectable population, with `CardDefinition` pointing at its originating compiled code. Duplicate public card IDs and broken published compiled cards must fail content indexing/link validation with source-located diagnostics; never silently omit an invalid published card or keep executing its stale last-good body. Source-local untagged cards are never random candidates unless an author explicitly elects to make them selectable by tags.
5. Global card binding content: compiled card sources can have companion typed asset bindings; existing binding values must be preserved. If the current importer requires a `*.bindings.asset` before compilation, create the necessary companions **programmatically through supported Unity editor APIs**. Do **not** require hand-editing serialized YAML or implementing the future Studio UI. Avoid the importer reimport recursion/circular dependency trap; verify import changes converge to one settled index revision and unchanged refresh is a no-op (see Index lifecycle below).
6. Published content root vs development: only **published production card sources** join the normal global pool; validation/examples remain separately classified as test content, not silently offered to players. Publishing means placing authored content in the global production discovery scope, **not registering it with an individual scene**. Do not create a per-scene opt-in/blacklist to compensate for development cards.
7. Extend project-wide card validation: allowed/compatible tags, typed requirements, source binding validity, duplicate IDs, unresolved assets, and diagnostic when a globally eligible card uses an unavailable scene-specific resource. A missing/invalid card-owned content asset is a publication/link error. A valid card requiring a resource absent from the current scene is ineligible with a clear candidate rejection reason; it must not reject the whole scene or unrelated cards. Explicit execution reports that missing resource at the call site before invoking the card. These are scoped content/resource checks, not a new generalized capability gate. Current First Contact equipment coverage for all eligible owned items stays a validation check of **global published content**, not a list inside the scene.
8. Runtime build safety: generated global index is automatically refreshed on content import/publish and required for player execution, with deterministic ordering and no Editor `AssetDatabase` lookup at runtime. Build prep must validate it is current; do not launch a build here. Avoid content GUID/path assumptions that break AssetDatabase.MoveAsset.

## Gate C

Evidence includes one *new-card/no-scene-change* test diff, duplicate ID test, requirement test, and source/link relocation tests. No scene authoring UI is built in this ticket.

## Code-level requirements missing from the initial design

**Compile/link boundary and names.** `DazStoryCompiler` currently rejects `play` and literal `Director.Execute` targets absent from the same source. Introduce an explicit compile/link contract for published external targets, with unresolved-target diagnostics at link time; do not simply remove validation. Preserve direct local `play Intro`. Public tagged card IDs are unique across the global pool. Untagged helper cards are source-local: two sources may each have `Intro` without collision or random eligibility. Define local-first explicit lookup, then unique public ID lookup; diagnose ambiguous local/public shadowing instead of silently choosing a different card. Nested calls resolve in the calling card's source scope. Resolve dynamic explicit IDs with the same rules and source diagnostics.

**Relocation completeness.** Relocate `StoryInstruction.expression`, argument expressions, `CardRequirement.Expression` and `completionTarget` as **expression indexes**, preserving sentinel `-1`. Relocate `jump`, `StoryEntry.start/end` and `StoryBindingUse.instruction` as **instruction indexes**. `loop` is a repeat identity, not an instruction address: remap it consistently to avoid collisions across linked units in the machine repeat-state table. Preserve nested explicit target resolution and repeat begin/end pairing. `StoryAtom.count` on AndSkip/OrSkip is an index within that expression; do not add an instruction or expression-array offset to it. Keep a source identity with every linked entry/command. Link without mutating shared imported program arrays in place; otherwise opening a second scene can double-offset the same asset.

**Binding ownership.** `CompiledStoryAsset.content` and `PerformanceStoryHost` currently provide a single `StoryContentBindings` for the whole execution. Relocating instructions alone is insufficient. Pose/gesture/motion/shader/dialogue lookup must use the originating source's companion bindings; the same alias may legitimately mean different assets in two files. Scene roles/locations resolve against the active `StorySceneBindings`, not against serialized transforms captured from First Contact. Carry source binding context across nested and awaited/unawaited work and restore the caller correctly; a mutable global "current bindings" variable is insufficient for pending commands. Preserve dialogue hash/transcript validation and engineering-placeholder metadata.

**Scope resource checks.** `StoryContentBindings.Diagnostics` currently validates every binding/dialogue in a program and demands all equipment coverage whenever it sees a Warmup tag. Replace that per-file assumption: validate published owned content at index/link time, check scene resources for the selected card's reachable local/public call closure, and keep First Contact's equipment-coverage regression against the assembled global pool. An unrelated global card needing another scene's seat/mark must not prevent First Contact from starting. Optional-equipment skip and no-positive-progress failure semantics remain unchanged.

**Index lifecycle.** One generated application/content asset is automatically reachable at runtime, including when the user directly Plays a saved scene. No scene registration or per-scene serialized copy of global cards. Track source and binding changes, add/delete/move/rename, compile failure and recovery; delete stale entries. Keep original GUID/source identity through moves. Index refresh must converge without recursive import/SaveAssets loops: one settled revision for a real content change and no writes on a second unchanged pass, rather than an untestable promise of exactly one Unity callback. Invalidate caches across editor reload and Play sessions including disabled domain reload; running sessions retain a stable population snapshot. Build-time validation reports an absent/stale/invalid index without rebuilding scenes or starting gameplay.

**Session ownership and determinism.** Linking another source does not create another Director/history, RNG streams, signal hub, completion counter or cancellation scope. All cards still run through the same interpreter and host contract. Preserve pending-work drain before progress credit, failure/Stop cancellation, UI event cleanup and silent toy errors. Define deterministic source/declaration ordering independent of filesystem enumeration and moves; preserve the existing migrated candidate order so seed 82017 matches the captured baseline. New cards may change selection, as intended; removing a temporary card restores the old population/order. Do not introduce a manually maintained card membership list to obtain that ordering.

**Migrate real consumers.** Update `StoryProgramSequence`/compiled `StoryRunner` execution, the compiled asset Inspector, `StoryPlaybackWindow`, source checks and First Contact setup helpers to consume the same linked view. Preserve legacy JSON and C# sequence APIs. `tests/DazPose.Story.Tests/DazPose.Story.Tests.csproj` currently copies only FirstContact.dazstory, and `LanguageTests`/`DirectorTests.Actual()` compile it alone. Update their fixtures to compile/link the actual extracted published sources and bindings; do not make tests green by leaving duplicate embedded cards or weakening the full-session assertions. Combined migrated content retains 18 original declarations and 19 original dialogue entries; individual source-file counts will change.
