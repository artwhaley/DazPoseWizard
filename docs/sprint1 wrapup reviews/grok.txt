Bridging the hand to the member
The grip stack is a column follower. The male is not yet a column.
Contract the fingers actually understand:
C#IGripTarget.Evaluate(position01) → GripFrame { Center, Tangent, Normal, Radius }
world meters, analytic cylinder. MotionDriver already supplies Position01. Once Grip is Active, the controller samples that clock every frame. There is no GripFollowMotionDriver() to write. Following is automatic. The missing work is making the shaft speak that contract.
What the male has today:

Frozen erect skeleton + ErectionToFlaccid blendshape (Plan C). Endpoints are numerically dead-on. Intermediates are not visually accepted.
At flaccid, bones lie. Shaft7 is ~150 mm off the geometry line. You cannot drive contact from bones unless Erection01 ≈ 1.
Baked 33-station centerlines in root space, one lerped radius (2.06 → 2.33 cm). Line length shortens through the midpoint (19 → 15 → 14 → 18 → 23 cm). That polyline is a review gizmo, not a certified column.
Unskinned shell. Compliance is gated: erect and shell hidden. Manual ±5° on shaft1/shaft4 plus a distributed bend. No coupling from the hand.
Donor pelvis follow exists only as LateUpdate on the proof controller.
No colliders. Fingers never see the mesh. Solver is an infinite cylinder (RadialDistance ignores axial bounds), so a real glans/tip will false-contact past the end.

Recommended T0 for the 2-minute scene — do not overbuild:

New production type PartnerShaftGripTarget : MonoBehaviour, IGripTarget on the male. Not the test controller. Evaluate in world space: live shaft1–7 + glans-plane tip at Erection01 = 1, reference Normal from the partner’s forward, per-station radius from the already-derived cross-sections (erect ~23 mm, not the rod’s 35 mm).
Lock the first job to erect. Flaccid bone contact is a later morph-or-rebake problem. Document that. Don’t lerp the two polylines for stroke.
Stop special-casing GripContactRod in the planner. Give IGripTarget a cheap IsLinear / sample-span hint, or certify a polyline. A bending shaft as a “general target” will trip TargetMovedBeyondPlan after three replans.
Donor pelvis follow becomes a tiny production component, always on, not a proof slider.
Put Caine in the lounge (or a combined authoring scene) posed inside Lara’s 0.20–0.95 arm envelope, or accept one walk-to-grip. Right now the actors have never been in the same Play Mode.
Compliance, one-way, tiny. Drive shaft1 / mid-chain from grip strength + a lag/spring, ±3–5°, restore to captured erect base every frame (the proof controller already does non-accumulating offsets). After the offset, re-sample the live world frame so the hand rides the bent column. Do not iterate contact→mesh→contact.
Squeeze: cheat first, morph later. Shrink GripFrame.Radius a millimetre or two with gripStrength01 so fingers close in. Real radial morphs (Shaft Inflate negative, glans flatten) are not in the Unity mesh. Testicle squeeze morphs are the wrong organ. Don’t export a 252-modifier inventory for this week.
Shell stays on and ignored for contact until it is skinned or morph-synced. Hiding it to “see bones” is a proof UI, not a scene look.

What you will still not have: left hand, shoulder shrug, finite capsule vs infinite cylinder, length-stable Position01 across erection, squeeze that deforms the mesh, flaccid contact.

Wardrobe: guts good, save wrong, UI lying
You are right that this is mostly workflow. You are slightly wrong that it is only UI. Save does not bake the thing the runtime treats as source of truth.
The model is good. Base / 1 / 2, ceiling, VisibleMask, skip empty layers, hair off the undress stack, shoes as ordinary pieces, fit states per reachable mask, queued Outfit / TryRemoveLayer / TryAddLayer. Facade on SuccubusPerformer matches the 10-04 spec.
Why layer assignment “doesn’t take” after Save:
Two stores. Configuration.Assignments got the new layers. WardrobePreset.Parts[].layer stayed at import default (Base). Fit states were recompiled for the new masks.
ClothingSetupWindow.SaveConfiguration writes session layers onto the configuration, then calls preset.ConfigureGenerated(..., pair.Key.Parts, ...) — the old parts. The test fixture builder and the publisher both copy assignment layers onto parts. The artist Save path forgot that merge.
Then PerformerWardrobe.ResolveLayer uses configuration only when ConfigurationApplies() (candidate preview, or generation hash matches a release). Otherwise it reads preset.Parts. Lounge / released / hash mismatch → populated mask is Base-only → either everything comes off at once, or FitNotAvailable because the compiled masks don’t match.
Living evidence: first-outfit config has dress=1, panties=2; the preset asset still has both on layer 0.
Other ways it feels broken:

Layer 1 / Layer 2 are toggles. Clicking the active one silently sets Base. There is no Base control and no “this is layer X” badge.
Help text says Base is “always the first layer removed.” Runtime removes highest first. Artists who believe the help text will put the coat on Base and think Remove is broken.
Save is disabled in Play. Clothes only appear after Play → Load outfit. Edit-mode assignment has zero visual.
Naked button is Outfit("unclothed"), which forgets the outfit. Spec wanted naked preview (ceiling −1). Add after Naked is NoOutfitSelected.
Outfit("first-outfit") string resolve refuses an unreleased catalog. Clothing Setup cheats with the typed preset overload + allowCandidatePreview.
Compile-all-presets on Save: one Needs Fit anywhere aborts the whole configuration.
FirstPerformanceVoid has no wardrobe component. The lounge cannot change clothes no matter how correct Clothing Setup is.
Inventory is built once at Play Awake. Even a correct Save does nothing until you re-enter Play.
