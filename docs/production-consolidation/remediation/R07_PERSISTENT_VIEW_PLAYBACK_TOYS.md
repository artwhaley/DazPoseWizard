Every accepted intent gets a monotonically increasing per-owner generation. Existing suitable request IDs may be reused. A captured cleanup checks generation/current intent even after its Awaitable has settled. Raw facade calls must supersede these identities too. Do not use a run-global CancelAll on actor Stop.
2. Stop clears only current run-owned state: return owned pose/expression to declared defaults; clear owned gaze/tracking/aura; release owned held arrival/contact immediately; cancel exact pending speech/wardrobe requests. Preserve committed wardrobe appearance. Do not undo completed root/player movement on Stop. Explicit host Reset handles initial placement/outfit.

Match PlayerViewCompletion.Completed; TargetLost/Superseded/disabled fail unless stopped. Preserve independent view channels.

Every explicit start/reset/source replacement advances the generation; cleanup stops only its captured command generation. Ordinary pause/resume/time advancement is not a new ownership generation.

Reject missing required devices with context; optional absence is skipped by the host via capability query. Preserve backend pause/disconnect semantics. Implement the exact delivery contract below; animation completion alone is not hardware delivery success.

Animated release wrapper captures the exact active generation and waits until its weight/motion suppression are released; Stop cancels immediately. A later acquisition is never released by a stale waiter. Plain ReleaseGrip remains available as a scoped void forwarding command with ownership validation.

## Fixed toy completion and delivery contract

`ScopedToys` exposes `VibrateAsync` and `OscillateAsync` (level, optional channel overload), `RampVibrationAsync`/`RampOscillationAsync` (target, seconds, optional channel overload), and `MoveToAsync` (position, seconds), returning `Awaitable<PerformanceToyResult>`. Public result is immutable: Operation, SuccessfulBindings, defensively copied IReadOnlyList<string> Errors, Succeeded. Play/Follow/StopFollowing remain synchronous ownership commands. Connection/scanning remain explicit service setup outside the run. `PerformanceRun.HasToys` reports a bound active service; `ScopedToys.CanOutput(capability, int? channel=null)` reports connected matching routes without sending output. Absent optional toys are skipped explicitly by the host. Requested output with zero routes fails before dispatch.

Reuse ToyControlService's existing owner revisions, coalesced queue and DispatchOutputAsync; do not build a second dispatch path. Add internal per-command outcome tracking attached to captured OutputOwner/revision. Record backend exceptions, disconnect and supersession against those owners, not shared LastOutputError. At ramp/move end, wait for the final owned dispatch for each selected binding to finish; count acknowledged bindings and return their errors. Intermediate samples may be coalesced normally. A superseded or disconnected final dispatch is a failure unless the run deliberately stopped. The existing internal ToyCommandReport can supply data, but must not leak as a public type. No blocking Task.Wait on Unity's thread. Feed the public result into R06's single kernel; any error or zero successful bindings fails the scoped command and stops siblings. Legacy void/non-generic methods retain their signatures and behavior.

Add mock checks for delayed final acknowledgement, backend exception, no routes, route replacement, disconnect before final acknowledgement, coalesced intermediate updates and deliberate Stop. Verify no duplicate sends and no false success from finishing the interpolation timer.
