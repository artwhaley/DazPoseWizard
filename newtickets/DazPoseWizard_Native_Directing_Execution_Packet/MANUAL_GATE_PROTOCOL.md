# Manual Unity gate protocol — Art runs Unity; executor never does

## Unambiguous division of work

**Executor:** implement/read/test source, run .NET and static validation outside Unity, prepare a **separate isolated project copy** and ignored diagnostics, then **pause and ask Art**. **Do not start any Unity process or tool**, even batch/headless, EditMode CLI tests, CI Unity jobs, Play, Build, standalone player, Unity Hub or remote GUI. Do not direct computer-use tools at Unity. **Art:** owns all Unity launch, import, inspection, clicking, compiling, menu execution, screenshots and optional Play testing. Art may answer simply `PASS`, `FAIL` or `BLOCKED` plus pasted console/report text and observations.

The executor is **required to ask for assistance early and often**. At each gate: freeze dependent implementation; present (1) reason for pause, (2) exact isolated project path (not a source asset shared with the real project), (3) specific menu and 3–6 manual clicks, (4) exact ignored report path and required screenshot/console details, (5) what PASS looks like, and (6) explicit request for Art's response. Do not promise an exact file path/menu before implementing it; the defaults below are **required names unless a documented, equivalent name was implemented**. **Never infer PASS from no response.** Record `WAITING ON ART` / native `NOT RUN` / overall `PARTIAL` until confirmation.

## Fixture containment and diagnostic implementation

1. N00 performs read-only baseline checks first. A saved scene copy **does not isolate** `FirstContact.bindings.asset` or the global card index. Create an independent **physical copy** of the validation Unity **project** with its own `Assets`, `ProjectSettings`, packages, GUIDs and imported source/binding/index assets; document location and baseline hashes. **Do not use symbolic links to source Assets or indexes.** Never run importer code just to prepare it. Avoid original asset mutation; `SaveAssetIfDirty` can bypass `OnWillSaveAssets`.
   - The executor still implements in the authoritative repository. **Before each Art gate**, synchronize changed **code plus `.meta` and assembly definitions** into the independent project (or safely recopy the whole project to a new isolated fixture), while **preserving that fixture's independent source/content/index/scene baseline**. Record a code hash/commit check showing the Editor will compile the **current implementation**, not a stale N00 snapshot. No auto Unity import. If selective sync might overwrite a real authored asset or fixture change, stop and ask Art; never blanket-sync unsafe paths.
2. Native diagnostics are `MenuItem` actions compiled into the Editor assembly, **not** `[InitializeOnLoad]` side effects and not automatic at import/startup. Menu root: `DazPose > Story > Native Directing Diagnostics`. Actions must confirm the exact isolated project and disposable saved scene; refuse production scenes and unresolved bindings; show an upfront confirmation before any write or deliberate scene save. Include a **Read-only Status / Export Report** action. No diagnostic silently changes global catalogs, assets or active saved scenes.
3. Art runs these in **Edit Mode**, never Play. For each report include SHA/project path/scene path, Unity version, timestamps, diagnostic version, before/after scene dirty status, exact transform/bone/material/prefab diff, save outcome, exceptions, and `PASS/FAIL` subchecks. Write JSON and readable text to `<isolated-project>/Temp/NativeDirectingDiagnostics/Gx_<timestamp>/`; no source/asset writes for logs. If Unity compilation fails so the menu never appears, Art provides the Console text; executor repairs source and repeats the same gate.
4. Any native diagnostic that stages/saves must establish a safe baseline, own its temporary state, restore after completion or exception, and avoid accidental writes. **Do not wrap a multi-frame visual comparison in one immediate `try/finally` that restores the rig before Art sees a different Game frame.** Use an explicit temporary diagnostic control with **Shift → observe Game frame → Restore**, and cleanup on window close/scene close/compile; refuse Save while G1 shift is armed because N02's save guard is not built yet. Before source code can claim Save safe, test on an isolated disposable scene; failure evidence may require restoring copy from baseline, never production by guesswork.
5. Each novel preview-owned property family — camera root, Lara bones, renderer enabled/materials, body visibility, seating transform, pose sampling — must be added to the ledger and rerun through relevant **Art-operated** save/Undo/Stop checks before safety is claimed. G2 is initial integrated proof, **not** final blanket approval of unimplemented material/seating branches.

## G1 — after N01: real saved Game camera feasibility (hard stop)

- Executor prepares scene/host mapping, menu `DazPose > Story > Native Directing Diagnostics > G1 Camera Proof`, and fixture instructions. G1 must **not depend on N02 lease**. Its small native diagnostic panel has explicit **Shift Camera Rig** and **Restore Camera Rig** buttons with saved baseline and guarded cleanup, no Save/Play or extra Camera/RenderTexture. It holds the temporary transform long enough for Game view to repaint; **never self-clicks**.
- **Ask Art:** open isolated Unity project in 6000.5.9f1; let it compile/import; open disposable FirstContact scene and standard Scene and Game tabs; inspect PlayerView.MainCamera/viewRig/headPose; click **G1 Camera Proof**, click **Shift Camera Rig**, observe/take Game screenshot, then click **Restore Camera Rig** and observe second frame; send report, both screenshots and Console errors. **Do not save while G1 is shifted**; the panel must block/warn on that action.
- PASS: Game view uses the real existing camera, shows different images at different staged marks in Edit Mode, and leaves root/scene/prefab state restored. FAIL/BLOCKED: no Edit Mode rendering, missing ref, HDRP error, unrestored transform. **No N02+ until Art confirms PASS.**

## G2 — after N04: minimal camera + standing Lara + save proof (hard stop)

- Executor implements menu `... > G2 Standing and Save Proof` and a 3–5 step manual walkthrough using `Camera.StartAt(camera_start)`, `Lara.LocomoteTo(stepforward)`, `Lara.PersistentPose(SexyVamp)` on real Lara; its report hashes/diffs baseline vs serialized scene and camera/actor/renderer fields. **N06's full cue transport does not exist yet**: G2 invokes a minimal, clearly-labelled fixed diagnostic projection against real source bindings, not a fake completed Studio transport. It must use the same N02 lease and N03/N04 adapters the product will reuse.
- **Ask Art:** open isolated disposable scene; click G2 to verify rig/standing shot; drag `stepforward` and `camera_start` with native gizmos while observing Game; invoke normal Ctrl+S during **preview-only** state and perform an explicit diagnostic **SaveScene of the disposable copy** to force serialization even if originally clean; then move one mark, Ctrl+S, Undo/Redo, Stop, reopen; return report, screenshots and any unexpected overrides.
- PASS: authored mark moves persist/undo; saved Lara/camera/bones/material/visibility do **not**; preview-only writes add no dirtiness/Undo entries; Stop preserves deliberately unsaved authored dirty state and new author-created prefab overrides. Art verifies the actual Game shot. No N05+ before PASS.

- PASS: each seat command matches its *own* runtime stable endpoint; persistent Lounging uses yaw + `SeatAnchor.position - sampledHip.position` translation; Approach shift alone does not shift settled hip; no drift; prefab overrides reflect only deliberate seat edits. No N06+ before PASS.

## G4 — during N10: full editor/regression acceptance (hard stop)

- Executor provides menu `... > G4 Full Regression Export` and concise human walkthrough with imported scene status, gesture completion/base pose, materials/MagicShader restoration, `[ExecuteAlways]` wardrobe behavior, global-card/branch visits, error halting, camera track, real HDRP/Game frames, all save paths and teardown. Test errors must not silently skip to later cues.
- **Ask Art:** use isolated project to click G4, inspect Console and both views, execute requested native save/Undo/reload/open-close/recompile steps **manually**, compare protected asset hashes and newly authored overrides, return screenshots/report. Separate **optional**, Art-owned Play/physical-grip checks from Edit Mode release gates.
- PASS: all mandatory A-cases backed by Art's actual evidence. Without it, deliver source and report as `PARTIAL / WAITING ON ART`; **do not claim complete** or bypass the gate. Delete retired preview implementation only after G1–G3 previously passed; if G4 fails, repair and repeat.
