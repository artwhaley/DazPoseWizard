## Phase 3 binding/manifest pipeline

**Stage 1: syntax/semantic parse into requirements**. Add `DazStoryCompiler.Analyze(source,path,options)` yielding flat source model/diagnostics and `StoryBindingRequirement[]` assembled via **existing StoryVocabulary typed parameter declarations** and literal dialogue occurrences, independently of any assignment. Requirement: `{stableOwnerSourceGuid,kind,publicName,sourceUseLocations[],expectedType,dialogueTranscript?}`. No duplicate manual tables of vocabulary kinds. Static source `Card` declarations can be analyzed without scene. Calls with resolvable symbolic literal arguments produce typed unresolved placeholders; unknown verb/wrong operand emits diagnostics even if resource missing. **No binding assignment necessary to complete analysis**.

**Stage 2: resolve/compile**. Validate typed assignments (content asset or scene locations), then produce existing `CompiledStoryProgram`. Support separate status `SyntaxValid`, `BindingsIncomplete`, `Ready` and per-use warnings. The import pipeline should provide a compiled asset/requirements even if incomplete, rather than `Context.LogImportError` for normal new unbound symbols. Actual Play/build still blocks precisely on unresolved required objects. If compiler currently has dependency on `Symbols()` to type-check, refactor to derive expected binding kind from `StoryVocabulary.bindingParameters` and compiler contexts; keep compatibility wrappers for existing C# tests/callers. Legacy JSON remains legacy only. Runtime execution stays one StoryMachine.

**Stage 3: reconcile**. `SourceBindingReconciler` maintains one source-owned typed `StoryContentBindings` companion keyed by `{sourceGUID,kind,semanticAlias}`; dialogue keyed by existing `StoryDialogue.IdFor(transcript)` (retain hash policy). Prefer matching stable aliases; preserve values/posture and metadata. Newly found requirements get empty correctly typed records; removed records are displayed under `Unused/Orphaned`, not immediately deleted; collisions and alias type changes are explicit errors. Reconcile automatically on import/editor open using idempotent guarded apply and Undo where user-triggered; no reentrancy loops, no changes if no semantic diff. Compiled importer depends on companion asset correctly, but can analyze without it. Do not add `.asset` YAML editing steps to the user workflow.

Scene-owned `StorySceneBindings` remains on saved production host. A *scene requirement reconciler* adds/identifies typed location requests (placement, optional seat, focus, performer or player role) without fabricating gameplay positions. Create missing `Location` under `Authoring Marks` only by explicit author action; default preview placement follows deterministic selected-stage cursor, flagged UNPLACED; saved stage remains unchanged until confirmed. No `FirstContact` constant lists in general studio. Names are story symbols, not random GameObjects.

## Asset ownership and cross-scene reuse

A `.dazstory` program can explicitly play locally-authored narrative cards; all public selectable tagged cards under global published root are automatically indexed without scene registration. Each global source owns its own content companion; a named pose alias may resolve differently per source, matching existing `StoryLinkedContent.ContentFor(source)`. Scene spatial requirements are validated at eligibility evaluation; cards missing scene resources are rejected with reason (no silent call into missing object). The studio's Director candidate browser reads the global index and same eligibility rules. No copied/scoped scene card libraries.

## Scene tool save state

Authoring workspace state (panel split sizes, scroll, selected step, preview branch path, test seed, camera orbit) belongs in editor-only transient `SessionState` or EditorPrefs when appropriate, not serialized into a scene or source. Saved authored data stays in (1) `.dazstory` choreography, (2) source-owned content assignments, (3) Unity saved scene + `StorySceneBindings`. Optional named rehearsal scenario files are **test fixtures** under tests/authoring and contain seed, branch overrides, synthetic responses only. They never define scene choreography.

## Guardrails

- No asset/prefab/scene edits during preview tick. Preview cloned objects are never target of `EditorUtility.SetDirty`/`Undo.RecordObject`.
- Runtime performer material shader transitions and SALSA/pose sampling need preview adapters, not invoking live session work. Preview SALSA can listen/read current waveform but doesn't instantiate a live gameplay host or device; if full lipsync preview unsafe, show audio and safe face clip sampling with explicit capability diagnostic.
- Use `UnityEditor.EditorSceneManager`/`PreviewRenderUtility`/`AnimationMode` or Playables APIs carefully: in the selected implementation, **one owned isolated preview scene** and render owner must be documented, with all clones and their original object mappings; EditorWindow closes/disposes on reload and errors. The active production scene is never loaded as an editable preview copy or silently saved. Committing a mark operates on the original explicitly and uses Undo.
- Do not hardcode a FirstContact scene folder, symbolic role list or UI sizing in production studio code. FirstContact is integration acceptance, not infrastructure configuration.
