# P0.A1 — Production `WalkTo` runbook

## Implementation boundary

Production Lara remains `Assets/TestCharacter/lara.fbx` with its Generic DAZ skeleton. The editor baker reads the separate, already-configured `Assets/TestCharacter/laraHumanoid.fbx` Avatar and the installed KAWAII source FBXs. It does not change either model importer or any vendor asset.

The baker samples the Humanoid retarget proxy at 60 fps with Unity Foot IK enabled, matching the setting that fixed the leg appearance in the audit. It writes project-owned Generic transform clips plus separate planar root position/yaw curves under `Assets/Animations/Performer/Locomotion/`. The baked transforms contain the retargeted Foot IK result; the production performer does not run runtime Foot IK. The generated root trajectory is applied by `PerformerLocomotion`, and the runtime `Animator.applyRootMotion` setting is temporarily disabled while this profile is active to prevent double movement.

The initial source family is:

- `@KA_Walk01_Start.FBX` — original and Humanoid-mirrored starts.
- `@KA_Walk01.FBX` — loop.
- `@KA_Walk01_Stop.FBX` — original and Humanoid-mirrored stops.
- `@KA_TurnLeft_90.FBX`, `@KA_TurnRight_90.FBX`, `@KA_TurnLeft_180.FBX`, and `@KA_TurnRight_180.FBX`.

The bake command refuses to create or update the locomotion clips/profile unless it measures positive forward trajectory on Start/Loop/Stop and the expected signed root yaw on all four turn clips. The Walk01 pivot FBX is not part of this profile. Review its generated `docs/animation-audit/Walk01BakeReport.md`; its phase matches and support-foot identities are automatic estimates, and the report explicitly leaves visual seam acceptance to the manual test.

## Runtime behavior

`SuccubusPerformer` exposes:

```csharp
public void WalkTo(Vector3 worldPosition);
public void WalkTo(Transform target);
public Awaitable<LocomotionCompletion> WalkToAsync(Vector3 worldPosition);
public Awaitable<LocomotionCompletion> WalkToAsync(Transform target);
```

The `Vector3` overload faces the direction of travel. The `Transform` overload snapshots its world position and planar forward vector when called. The async result is `Arrived`, `Superseded`, or `PerformerDisabled`. A repeated active destination joins its current request; a different destination becomes current immediately. Short requests always begin with Start. If the target has not been reached when Start finishes, they blend into the closest matching Stop variant. At the target, movement ends and the current animation blends back to the persistent idle/pose. Short requests do not enter the walking loop from rest. This temporary behavior may cut Start or Stop at any foot phase; better authored short steps remain future work.

The body source mixer sits between persistent `PerformerBodyPose` and breathing/gaze/expression/blink. Pose intent continues to update underneath a walk; downstream gaze, expression, breath, blink, speech, and SALSA remain connected. Locomotion blends back to the most recently requested pose before reporting `Arrived`.

The profile starts at **0.665×**, 33% faster than the previous 0.5× setting. Body animation and root trajectory share this speed. Idle → locomotion blends over **0.5 seconds** with eased weights while the incoming animation advances from frame zero throughout the transition. Return to idle also blends over **0.5 seconds** while the outgoing Stop continues advancing. Motion-to-motion blends use **0.16 seconds**. Heading errors up to 45° use a gradual steering cap. Larger initial errors use the authored 90° or 180° turn clips and bounded yaw scaling. An in-motion reversal waits for the next phase-matched authored Stop A/B, completes that stop, turns in place with the appropriate 180° clip, then starts walking toward the latest destination. Travel follows the direct line to the requested target using authored planar distance timing. Long walks select the nearest gait-matched Stop, predict its authored endpoint, and ease the calculated position error into the root over the final 0.5 seconds of real playback. The completed Stop explicitly assigns the requested target X/Z coordinates. Final facing turns preserve that position, then the outgoing animation fades to idle over 0.5 seconds. Short walks retain Start/Stop truncation at the target.

This slice assumes a flat, clear floor in one room. It adds no navigation, obstacle avoidance, stairs, running, terrain/foot IK, seating, or `SitAt()`.

## ART'S P0.A1 WALK TEST

### Prepare the real performer

1. In Edit Mode, open `Assets/Scenes/PoseValidation.unity` and select Lara's performer root.
2. Run **Tools > DAZ Pose > Locomotion > Bake KAWAII Walk01 for Generic Lara**. This is the one-time content bake; it must finish without a root-trajectory error. Inspect the report and generated clips in `Assets/Animations/Performer/Locomotion/`.
3. With Lara's root still selected, run **Tools > DAZ Pose > Development > Setup or Refresh Performer Pose Acceptance Harness**. It assigns the generated profile when present and creates/reuses a movable `P0.A1 WalkTo Target` marker. Save `PoseValidation.unity`.
4. Confirm the `SuccubusPerformer` Inspector shows `KawaiiWalk01Profile` in **Locomotion**, and the smoke panel's target field points to `P0.A1 WalkTo Target`.
5. Enter Play Mode. The added walk panel appears inside the existing performer smoke harness. No new scene or proxy performer is needed.

If baking stops with a trajectory error, do not assign an older/stale profile or try to test locomotion. Capture the first complete Console error and the generated bake report state; root extraction must be fixed before proceeding.

### Straight walks, seams, and stops

1. Set **Test distance** to **5 m**, then click **Ahead**. Watch `Starting → Walking → Stopping → Settling → Idle`, actor XZ movement, and the `Arrived` result. Confirm there is no transform snap and the actor stays on the same world Y.
2. Repeat **Ahead** at several distances using the test-distance slider. Compare the two stop variant names and note the selected stop, gait phase, predicted endpoint, and correction magnitude near the stop. Repeat each distance to exercise both original/mirrored starts and stops.
3. Test **0.5 m**, **1 m**, **2.5 m**, and **3 m**. Each should begin with Start. Very short walks should reach the target during Start and blend to idle; those with room after Start should enter Stop, then blend to idle at the target. They should not select the walking loop. The report's minimum distance is the threshold for the full Start/Loop/Stop maneuver, not a restriction on short requests.
4. Watch both transition points closely: Start → Loop and Loop → Stop. A clean numeric report is not a pass if either seam visibly hitches, the feet skate, or a large crossfade makes the legs mushy.

### Direction, turns, and final facing

1. From a reset position, try **30° L/R**, **60° L/R**, **90° L/R**, and **120° L/R**. The 30° cases should not select an in-place turn. Larger initial heading errors should show the selected authored turn and turn clip time.
2. Try **Behind-Left**, **Directly Behind**, and **Behind-Right**. Note the selected turn and whether the motion direction is believable.
3. While an **Ahead** walk is underway, request a behind direction to exercise latest-target-wins and the phase-matched Stop → 180° Turn → Start reversal. The first command should resolve as `Superseded`; the replacement should stop on a gait-matched phase, turn in place, and resume toward the new destination without snapping idle.
4. Move `P0.A1 WalkTo Target` to a clear position several meters away, rotate its blue forward axis toward the desired arrival facing, then click **WalkTo Transform**. Confirm it reaches the position and finishes facing that axis.

### Performer coexistence and lifecycle

1. During a walk, activate gaze toward the camera and click **Say A** with a non-silent clip. Confirm head/eye gaze and SALSA continue while the lower body walks.
2. During another walk, request an expression and a different persistent Pose. Confirm locomotion keeps the visible body until it stops, then the latest Pose appears; expression, breath, and blink continue throughout.
3. Start another walk and request a second destination before arrival. Read the numbered completion history: the old request should report `Superseded`, the latest should report `Arrived`.
4. Start a walk and disable the `SuccubusPerformer` component before arrival. Its request should report `PerformerDisabled`. Re-enable it and repeat a walk. The displayed Playable count should return to the same value after each enable, not grow each cycle.

### Questions to report before seating work

- Does Start → Loop now feel continuous?
- Does Loop → Stop now feel continuous?
- Does 0.665× feel like the right speed?
- Are the warped turns still believable?
- Does she stop at the target, and does the 0.5-second fade into idle look smooth?
- Does this feel like Lara walking somewhere rather than a game locomotion controller?

P0.A1 stops here. `SitAt()` and all seating behavior remain out of scope.
